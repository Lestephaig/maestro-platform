# Задача 5. Показывать баннер привязки Telegram

## Зависимости

Сначала должна быть выполнена задача №2.

## Цель

При входе авторизованного пользователя на сайт предлагать привязать Telegram, если он ещё не привязан.

## Перед началом

Изучи layout авторизованной части сайта, процесс входа, получение данных текущего пользователя и существующие баннеры или уведомления. Используй текущую дизайн-систему.

## Требования

1. После успешного входа или восстановления авторизованной сессии проверяй статус привязки Telegram.
2. Если Telegram не привязан, показывай заметный, но не блокирующий интерфейс баннер с краткой пользой: оперативные уведомления о сообщениях и новых публикациях.
3. Вся кликабельная область баннера или явная CTA-кнопка должна запускать существующий сценарий привязки Telegram из задачи №2.
4. Баннер можно закрыть. После закрытия он скрывается до следующей новой авторизованной сессии, но пользователь в любой момент может выполнить привязку через настройки.
5. После успешной привязки баннер должен исчезнуть без обязательной полной перезагрузки страницы.
6. Не показывай баннер:
   - неавторизованным посетителям;
   - пользователям с уже привязанным Telegram;
   - на экране, где уже открыт сценарий привязки.
7. Обеспечь корректное отображение на desktop и mobile, доступность с клавиатуры и понятный focus state.
8. Не делай модальное окно, блокирующее работу с сайтом.
9. Добавь frontend-тесты условий показа, закрытия и перехода к привязке.

## Критерии приёмки

- Непривязанный пользователь видит баннер один раз за сессию.
- Клик запускает корректный сценарий привязки.
- Привязанный пользователь баннер не видит.
- Закрытие и обновление статуса работают без ошибок.
- Вёрстка корректна на мобильных и настольных экранах.

## Отчёт по завершении

Укажи место размещения компонента, правила показа и скрытия, способ хранения состояния текущей сессии и результаты тестов.
