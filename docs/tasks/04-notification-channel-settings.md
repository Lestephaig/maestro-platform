# Задача 4. Добавить переключатели каналов уведомлений

## Зависимости

Желательно выполнить после задач №1 и №2 и до задачи №3.

## Цель

Добавить в настройки аккаунта независимое управление email- и Telegram-уведомлениями. Все последующие уведомления должны использовать единый сервис проверки выбранных каналов.

## Перед началом

Изучи текущую модель настроек пользователя, существующие email-уведомления и UI страницы аккаунта. Если в проекте уже есть настройки уведомлений, расширь их вместо создания параллельной сущности.

## Требования

1. Добавь два переключателя:
   - «Получать уведомления по email»;
   - «Получать уведомления в Telegram».
2. Для всех существующих и новых пользователей email-уведомления должны быть включены по умолчанию. Миграция не должна случайно отключить текущие уведомления.
3. Telegram-уведомления по умолчанию выключены до привязки аккаунта. После успешной привязки их можно автоматически включить.
4. Если Telegram не привязан:
   - переключатель Telegram должен быть недоступен или его включение должно предлагать привязку;
   - UI должен ясно объяснять причину;
   - нельзя сохранять фактически активный Telegram-канал без `chat_id`.
5. Отключение Telegram-уведомлений не должно отвязывать аккаунт.
6. Отключение email не должно удалять или менять email пользователя.
7. Добавь backend API чтения и изменения настроек с авторизацией и валидацией.
8. Создай единый сервис определения активных каналов, который смогут использовать сообщения, объявления и уведомления о музыкантах.
9. Предусмотри корректную обработку отсутствующих настроек у старых пользователей.
10. Добавь миграции, frontend- и backend-тесты для всех сочетаний переключателей.

## Критерии приёмки

- У существующих пользователей email остаётся включённым после миграции.
- Каждый канал можно включать и отключать независимо.
- Telegram нельзя активировать без привязанного аккаунта.
- Настройки сохраняются после перезагрузки страницы.
- Единый сервис возвращает правильные активные каналы для всех комбинаций.

## Отчёт по завершении

Опиши значения по умолчанию, миграцию существующих пользователей, API, поведение UI без привязки и результаты тестов.
