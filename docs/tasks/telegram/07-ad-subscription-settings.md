# Задача 7. Добавить настройки подписки на объявления

## Цель

На странице «Объявления» дать авторизованному пользователю возможность настроить подписку на новые объявления по нескольким типам, стране и городу.

## Перед началом

Изучи модель объявлений, справочники типов, стран и городов, текущие фильтры страницы, UI-компоненты и правила публикации объявлений. Повторно используй существующие справочники и селекты.

## Интерфейс

1. Добавь на страницу «Объявления» кнопку «Настроить подписку». Если подписка уже настроена, текст может меняться на «Изменить подписку».
2. По кнопке открывай модальное окно с затемнением и визуальным blur фона.
3. В модальном окне должны быть:
   - множественный выбор типов объявлений;
   - выбор страны;
   - выбор города;
   - признак активности подписки;
   - действия «Сохранить», «Отключить подписку» и «Отмена».
4. Используй связанные справочники: список городов должен учитывать выбранную страну, если такая связь уже поддерживается проектом.
5. Сделай модальное окно адаптивным и доступным: focus trap, закрытие по Escape, корректные подписи полей и возврат фокуса на кнопку.

## Правила фильтрации

- Можно выбрать несколько типов объявлений; совпадение хотя бы с одним выбранным типом считается подходящим.
- Если типы не выбраны, не фильтровать по типу.
- Если страна не выбрана, не фильтровать по стране.
- Если город не выбран, не фильтровать по городу.
- Пустое поле означает «любое значение», а не ошибку.

## Backend

1. Добавь модель настроек подписки, миграцию и API чтения, сохранения и отключения.
2. Для первой версии достаточно одной конфигурации подписки на объявления на пользователя с несколькими выбранными типами.
3. Сохраняй ссылки на существующие справочники или стабильные идентификаторы, не копируй их текстовые значения без необходимости.
4. Авторизуй все операции и разрешай пользователю изменять только собственную подписку.
5. Вынеси проверку соответствия объявления подписке в отдельный тестируемый сервис, который будет использован в задаче №7.
6. Добавь тесты wildcard-логики пустых полей, множественного выбора типов, прав доступа и UI модального окна.

## Не входит в задачу

- Фактическая отправка уведомлений при создании объявления — это задача №8.

## Критерии приёмки

- Пользователь может создать, изменить и отключить подписку.
- Сохранённые параметры восстанавливаются при повторном открытии окна.
- Незаполненные поля не ограничивают выборку.
- Пользователь не может читать или изменять чужую подписку.
- Тесты matcher-сервиса и интерфейса проходят.

## Отчёт по завершении

Опиши модель данных, API, правила wildcard-сопоставления, повторно использованные справочники и результаты тестов.
