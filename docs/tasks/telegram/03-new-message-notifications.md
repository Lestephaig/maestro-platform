# Задача 3. Добавить Telegram-уведомления о новых сообщениях

## Зависимости

Должны быть выполнены задачи №1, №2 и №4.

## Цель

После нового личного сообщения в Maestro отправлять получателю уведомление по выбранным им каналам. Для Telegram уведомление должно содержать автора, короткий фрагмент сообщения и кнопку перехода в нужный диалог.

## Перед началом

Изучи текущий чат, момент фиксации сообщения в БД, существующую отправку email, очередь фоновых задач и маршруты frontend. Не создавай второй независимый механизм уведомлений, если можно расширить существующий.

## Требования

1. Создавай событие уведомления только после успешного сохранения сообщения и завершения транзакции.
2. Учитывай настройки каналов пользователя:
   - email отправляется только при включённом `email`;
   - Telegram отправляется только при включённом `Telegram` и наличии активной привязки;
   - если включены оба канала, отправляются оба уведомления;
   - если оба выключены, внешние уведомления не отправляются.
3. Telegram-уведомление должно содержать:
   - имя или отображаемое имя отправителя;
   - безопасно экранированный фрагмент сообщения разумной длины;
   - для сообщения без текста — обозначение вложения или типа содержимого;
   - inline-кнопку «Открыть сообщение» с прямой ссылкой на соответствующий диалог.
4. Не добавлять возможность ответа через Telegram. Первый контакт и переписка остаются внутри Maestro.
5. Не отправлять пользователю уведомления о его собственных сообщениях.
6. Отправку выполнять асинхронно с таймаутами и повторными попытками. Сбой внешнего канала не должен мешать сохранению сообщения.
7. Добавь идемпотентность по сочетанию сообщения, получателя и канала, чтобы повторная обработка не создавала дубль.
8. Не выводить полный текст личного сообщения в логи.
9. Добавь тесты матрицы настроек каналов, формирования ссылки, экранирования текста, повторной обработки и ошибки Telegram API.

## Не входит в задачу

- Ответы на сообщения через бота.
- Передача Telegram-контакта собеседнику.
- Подписки на объявления и музыкантов.

## Критерии приёмки

- Уведомления отправляются строго по настройкам пользователя.
- Кнопка открывает правильный диалог Maestro.
- Ошибка Telegram или email не влияет на создание сообщения.
- Повторная обработка не отправляет дубль.
- Тесты проходят.

## Отчёт по завершении

Опиши точку возникновения события, способ фоновой отправки, правило формирования preview, механизм идемпотентности и результаты тестов.
