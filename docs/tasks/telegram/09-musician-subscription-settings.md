# Задача 9. Добавить настройки подписки на музыкантов

## Цель

На странице «Музыканты» дать нанимателям и другим авторизованным пользователям возможность подписаться на появление исполнителей нужных типов, голосов и инструментов.

## Перед началом

Изучи модель профиля музыканта, существующие типы исполнителя, типы голосов, инструменты, фильтры страницы и момент, когда профиль становится публичным. Не создавай дублирующие справочники.

## Интерфейс

1. Добавь на страницу «Музыканты» кнопку «Настроить подписку» или «Изменить подписку» для уже настроенного варианта.
2. По кнопке открывай модальное окно с затемнением и blur фона.
3. Добавь множественный выбор типов исполнителя.
4. Динамически показывай связанные поля:
   - для вокальных типов — множественный выбор типов голоса;
   - для инструментальных типов — множественный выбор инструментов;
   - если выбраны оба вида, показывай оба поля.
5. При удалении типа исполнителя корректно очищай или игнорируй более не относящиеся к нему критерии.
6. Добавь признак активности и действия «Сохранить», «Отключить подписку» и «Отмена».
7. Сделай окно адаптивным и доступным: focus trap, Escape, подписи полей, корректный возврат фокуса.

## Правила сопоставления

- Несколько типов исполнителя объединяются по правилу «любой из выбранных».
- Для вокального исполнителя выбранные типы голоса объединяются по правилу «любой из выбранных».
- Для инструментального исполнителя выбранные инструменты объединяются по правилу «любой из выбранных».
- Пустой набор критериев соответствующего уровня означает отсутствие фильтрации по этому полю.
- Несвязанные критерии не должны случайно исключать профиль другого типа.

## Backend

1. Добавь модель подписки, миграцию и API чтения, сохранения и отключения.
2. Для первой версии достаточно одной конфигурации подписки на музыкантов на пользователя с множественными значениями.
3. Используй идентификаторы существующих справочников типов исполнителя, голосов и инструментов.
4. Пользователь может управлять только собственной подпиской.
5. Вынеси matcher профиля и подписки в отдельный сервис для задачи №10.
6. Добавь тесты динамических полей, очистки нерелевантных критериев, matcher-логики, прав доступа и сохранения настроек.

## Не входит в задачу

- Отправка уведомления при регистрации или публикации профиля — это задача №10.

## Критерии приёмки

- Пользователь может создать, изменить и отключить подписку.
- Поля голоса и инструмента отображаются только для соответствующих типов.
- Пустые критерии не ограничивают подбор.
- Сохранённые настройки корректно восстанавливаются.
- Matcher и UI покрыты тестами.

## Отчёт по завершении

Опиши модель данных, динамику полей, правила сопоставления, переиспользованные справочники и результаты тестов.
