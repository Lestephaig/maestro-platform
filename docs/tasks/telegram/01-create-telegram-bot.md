# Задача 1. Создать Telegram-бота Maestro

## Цель

Создать минимальный production-ready Telegram-бот Maestro, который в следующих этапах будет использоваться для привязки аккаунтов и отправки уведомлений. Бот должен разворачиваться на отдельном Linux-сервере в Нидерландах.

## Перед началом

Изучи структуру репозитория, `AGENTS.md`, документацию, текущий backend, Docker-конфигурацию, механизм конфигурации и фоновых задач. Выбери библиотеку Telegram, совместимую с существующим языком и стеком. Не создавай отдельный технологический стек без необходимости.

## Требования

1. Добавь отдельный сервис или модуль Telegram-бота в существующую архитектуру.
2. Реализуй команды:
   - `/start` — приветствие и базовая обработка параметра deep link; фактическая привязка будет добавлена в задаче №2;
   - `/help` — краткое описание назначения бота;
   - неизвестная команда — понятный ответ без ошибки.
3. Подготовь сервис отправки Telegram-сообщений, который можно будет вызывать из backend по `chat_id`, тексту и набору inline-кнопок.
4. Добавь структурированные логи, обработку ошибок, таймауты и корректное завершение процесса.
5. Не записывай токен бота и полный текст пользовательских сообщений в логи.
6. Добавь переменные окружения как минимум для токена бота, имени бота и базового URL Maestro. Обнови `.env.example`, но не добавляй реальные секреты.
7. Добавь Docker-сервис, healthcheck, политику перезапуска и краткую инструкцию запуска. Используй webhook или long polling в соответствии с текущей инфраструктурой; обоснуй выбор в документации.
8. Добавь тесты обработчиков команд и сервиса отправки сообщений с замоканным Telegram API.

## Не входит в задачу

- Привязка Telegram к пользователю.
- Уведомления о сообщениях, объявлениях или регистрациях.
- Настройки подписок.

## Критерии приёмки

- Бот запускается локально и через Docker.
- `/start` и `/help` возвращают корректные ответы.
- Сервис умеет отправить тестовое сообщение с inline-кнопкой.
- Ошибка Telegram API не приводит к падению процесса.
- Секреты отсутствуют в репозитории и логах.
- Автоматические тесты проходят.

## Отчёт по завершении

Перечисли изменённые файлы, команды запуска и проверки, новые переменные окружения, выбранный режим получения обновлений и известные ограничения.
