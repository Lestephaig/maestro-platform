# Система уведомлений

Система in-app, email и Telegram-уведомлений для Maestro Platform.

## Типы уведомлений

### 1. Новое сообщение в чате
- **Триггер**: успешная фиксация нового `chat.Message`
- **Получатель**: Пользователь, которому адресовано сообщение
- **Содержание**: Имя отправителя, фрагмент до 160 символов (либо тип вложения), ссылка на чат
- **Каналы**: независимо включённые email и Telegram; Telegram требует активной привязки

После успешной привязки Telegram-канал для новых сообщений включается
автоматически. Его можно независимо отключить в настройках уведомлений.

### 2. Приглашение в проект
- **Триггер**: Создание нового `InteractionParticipant` со статусом `pending`
- **Получатель**: Приглашенный пользователь
- **Содержание**: Название проекта, роль, имя пригласившего, ссылка на проект

### 3. Изменение статуса проекта
- **Триггер**: Изменение статуса проекта (`Interaction.status`)
- **Получатель**: Все участники проекта (кроме создателя, если он сам изменил статус)
- **Содержание**: Название проекта, старый и новый статус, ссылка на проект

### 4. Завершение проекта
- **Триггер**: Статус проекта изменен на `completed`
- **Получатель**: Все участники проекта
- **Содержание**: Название проекта, уведомление о завершении, ссылка на проект

## Настройка

### Фоновая доставка

Сигнал создаёт записи `NotificationDelivery` через `transaction.on_commit()`.
Сетевые вызовы выполняет отдельный worker (в Docker Compose он уже описан):

```bash
python manage.py process_notification_deliveries --watch
```

Для cron можно запускать одноразовый режим раз в минуту:

```bash
* * * * * cd /path/to/maestro-platform && python manage.py process_notification_deliveries
```

Неудачные попытки повторяются с экспоненциальной задержкой. Количество попыток,
базовая задержка и Telegram timeout задаются через переменные окружения.
`check_unread_messages` оставлен как совместимый fallback: он восстанавливает
пропущенные события для старых непрочитанных сообщений и обрабатывает очередь.

## Структура

- `models.py` - Модели Notification, настроек и идемпотентной доставки
- `deliveries.py` - Формирование событий и отправка по внешним каналам
- `utils.py` - Утилиты для отправки email уведомлений
- `signals.py` - Django сигналы для автоматических уведомлений
- `management/commands/process_notification_deliveries.py` - Фоновый worker
- `templates/notifications/emails/` - Шаблоны email уведомлений

## Защита от дубликатов

Уникальное ограничение по `(message, recipient, channel)` не позволяет повторной
постановке одного сообщения создать дубль доставки. Успешные записи больше не
выбираются worker-ом.
